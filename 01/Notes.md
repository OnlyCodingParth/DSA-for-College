## 2. Topic-Wise Detailed Explanation

### 2.1 Introduction to Data and Information
In computer science, a clear distinction exists between raw inputs and processed outputs.

* **Data**: Data is defined as a collection of raw facts, figures, observations, or unorganized symbols that by themselves do not carry specific meaning. Data serves as the raw material supplied to computing systems for processing.
  * **Examples**:
    * Student roll numbers: $101, 102$
    * Test marks: $85, 90, 95$
    * Student names: `abc`, `pqr`
    * Temperature readings: $32^\circ\text{C}, 34^\circ\text{C}$
* **Information**: Information is defined as processed, organized, and structured data that carries context, meaning, and utility for human decision-making or automated system operations.
  * **Worked Example**:
    * Raw Data input: $70, 80, 90$
    * Processing: Calculating the arithmetic mean $\frac{70 + 80 + 90}{3} = 80$
    * Meaningful Information output: $\text{Average Marks} = 80$

| Attribute | Data | Information |
| :--- | :--- | :--- |
| **Definition** | Raw facts, figures, and unorganized observations | Processed, organized, and structured data |
| **State** | Unorganized and unstructured | Organized and structured |
| **System Role** | Input provided to a computing system | Output generated by a computing system |
| **Meaning & Context**| Lacks standalone meaning or context | Possesses clear meaning, context, and utility |
| **Application** | Cannot be directly used for decision making | Serves as the direct basis for decision making |

### 2.2 Concept and Need of Data Structure
* **Definition**: A **Data Structure** is a specialized format for organizing, managing, processing, retrieving, and storing data in computer memory so that it can be accessed and modified efficiently. It establishes logical relationships between individual data elements.

#### Core Reasons Why Data Structures Are Needed
1. **Time Efficiency**: Choosing an appropriate data structure significantly reduces the execution time required to search, insert, delete, and sort data elements.
2. **Space Efficiency**: Proper structural selection prevents memory wastage by tailoring storage formats to exact data volume and dynamic allocation needs.
3. **Data Organization and Relationships**: Data structures accurately reflect real-world logical relationships between pieces of information (such as hierarchical user access or linear task sequences).

---

### 2.3 Real-World System Implementations
Data structures are deployed across various computer science domains to solve complex system engineering tasks:

1. **Operating Systems**: Utilize **Queues** and **Linked Lists** to manage CPU process scheduling queues, disk I/O request buffering, and dynamic memory chunk allocations.
2. **Database Management Systems (DBMS)**: Deploy **B-Trees** and **Hash Indexes** to power rapid search indexing across billions of record files stored on persistent storage.
3. **Web Browsers**: Rely on hierarchical **Tree formats** (Document Object Model / DOM) to represent nested HTML elements and render graphical interface layouts.
4. **GPS & Navigation Maps**: Use **Graphs** where vertices represent physical road intersections and edges represent roads to calculate the fastest route paths using shortest-path algorithms.
5. **Network Packet Routers**: Use **Stacks** and **Queues** to order incoming high-speed data stream packets in correct buffer sequences and manage retransmission requests.

### 2.4 Classification of Data Structures
Data structures are broadly categorized into two major types: **Primitive** and **Non-Primitive**.

```
                           Data Structure
                                 │
         ┌───────────────────────┴───────────────────────┐
     Primitive                                     Non-Primitive
  (int, float, char,                                     │
   double, boolean)                   ┌──────────────────┴──────────────────┐
                                   Linear                                Non-Linear
                          (Array, Linked List,                      (Tree, Graph,
                           Stack, Queue)                             Table)
```

#### 1. Primitive Data Structures
Primitive data structures are the most fundamental data types directly supported by a programming language. They store single values of specific formats.
* **Examples in C**: `int` (integers), `float` (single-precision floating-point), `char` (character), `double` (double-precision floating-point), `boolean` (logical boolean values).

#### 2. Non-Primitive Data Structures
Non-primitive data structures are more complex structures constructed by combining primitive data types. They store collections of values and are categorized based on element arrangements:

* **A. Linear Data Structures**: Data elements are arranged sequentially or linearly in a single dimension, where each element (except first and last) has a unique predecessor and successor.
  * **Array**: Fixed-size, contiguous memory arrangement of homogeneous data elements.
  * **Linked List**: Dynamic collection of nodes containing data and pointers to the next node.
  * **Stack**: Linear collection following the Last-In-First-Out (LIFO) access rule.
  * **Queue**: Linear collection following the First-In-First-Out (FIFO) access rule.
* **B. Non-Linear Data Structures**: Data elements are arranged hierarchically or in interconnected network patterns involving one-to-many, many-to-one, and many-to-many dimensional relationships.
  * **Tree**: Hierarchical structure consisting of root and child nodes (e.g., Binary Search Tree).
  * **Graph**: Network structure consisting of vertices (nodes) connected by edges (links).
  * **Table / Hash Table**: Key-value mapping structure for constant-time direct access.

### 2.5 Data Structure Operations
Data stored in data structures is manipulated using a standard set of operations:

1. **Traversing**: Accessing each element/record/node in a data structure exactly once to process or inspect its value (also referred to as "visiting" the node).
2. **Searching**: Finding the location or index of a specified target element within a data structure. Returns success if found, or failure if absent.
3. **Insertion**: Adding a new data element into an existing data structure. Successful when memory is available; results in an overflow state if the structure is full.
4. **Deletion**: Removing an existing element from a data structure and updating surrounding element links or indices.
5. **Sorting**: Arranging data elements into a specific logical order, such as ascending/descending numerical order or alphabetical order.
6. **Merging**: Combining elements from two separate sorted data structures into a single unified sorted structure.

### 2.6 Algorithms and Their Characteristics
* **Definition**: An **algorithm** is a finite, step-by-step sequence of unambiguous instructions executed in a precise order to solve a specific problem or compute a desired output.

#### Main Categories of Data Structure Algorithms
* **Search**: Algorithm to locate a target element in a data structure.
* **Sort**: Algorithm to reorder items according to a defined key.
* **Insert**: Algorithm to add a new item into a data structure.
* **Update**: Algorithm to modify an existing item at a target position.
* **Delete**: Algorithm to remove an item from a data structure.

#### Fundamental Characteristics of an Algorithm
To qualify as an algorithm, a procedure must satisfy six essential criteria:
1. **Unambiguous / Precise**: Every step, input, and output must be clear, precise, and lead to exactly one interpretation.
2. **Input**: Must have $0$ or more well-defined inputs.
3. **Output**: Must produce $1$ or more well-defined outputs matching the desired problem solution.
4. **Finiteness**: Must terminate after executing a finite number of steps.
5. **Feasibility**: Must be practical and executable using available system resources (time and memory).
6. **Language Independent**: Must consist of high-level step-by-step logic completely independent of any specific programming language syntax.

### 2.7 Algorithm Analysis and Performance Evaluation
When multiple algorithms solve the same problem, algorithm analysis provides quantitative metrics to evaluate and select the most efficient solution.

#### Objectives of Algorithm Analysis
1. Measure algorithm execution time.
2. Measure memory consumption.
3. Compare efficiency across competing algorithmic approaches.
4. Select the optimal algorithm for processing large-scale inputs.

#### Primary Resources in Performance Evaluation
Algorithm analysis evaluates two primary computational resources:

##### 1. Time Complexity
Time complexity represents the total time required by an algorithm to run to completion. Practically, it measures the rate of growth in key operations (such as comparisons, loop iterations, or memory assignments) relative to input size $n$.
* **Analytical Expression**:
  $$\text{Time Complexity} = \text{Compile Time} + \text{Run / Execution Time}$$
  *(Since compile time is a one-time fixed overhead, runtime analysis focuses on execution time as a function of input size $n$.)*

##### 2. Space Complexity
Space complexity represents the total memory space required by an algorithm during execution.
* **Components of Space Complexity**:
  1. **Fixed Part ($C$)**: Memory that remains independent of the input size $n$. Includes program code instructions, fixed simple variables, and constants.
  2. **Variable Part ($S_p(I)$)**: Memory that varies dynamically based on input size $n$. Includes dynamically allocated memory (`malloc`), arrays, and recursive function call stack frames.
* **General Mathematical Formula**:
  $$S(P) = C + S_p(I)$$
  where $C$ is the fixed memory space and $S_p(I)$ is the instance-dependent variable memory space.

* **Worked Space Complexity Example**:
  Consider the simple algorithm `SUM(A, B)`:
  * Step 1: Start
  * Step 2: $C = A + B + 10$
  * Step 3: Stop
  * *Analysis*: The algorithm uses three simple variables ($A, B, C$) and one numeric constant ($10$). The fixed space part $C = 1$, and the variable space part $S_p(I) = 3$ (for the variables). Total space requirement $S(P) = 1 + 3 = 4$ memory units (scaled by the byte size of the variable data types).

### 2.8 Algorithm Cases
An algorithm's performance varies depending on the initial arrangement or state of the input data:

1. **Best Case Analysis**: Defines the input conditions for which the algorithm requires the absolute minimum execution time or operations.
   * *Example*: In linear search over array $[1, 2, 3, 4, 5, 6, 7, 8]$, if the target key is $1$, it is found in the very first comparison at index $0$.
2. **Average Case Analysis**: Defines the expected execution time averaged over all possible random permutations of an input sequence of size $n$.
   * *Example*: In linear search, if the key $4$ occurs near the middle, the average number of required comparisons is $\frac{n + 1}{2}$.
3. **Worst Case Analysis**: Defines the input conditions for which the algorithm takes the absolute maximum execution time or operations. This provides an upper guarantee on running time.
   * *Example*: In linear search, if the key is $8$ (at the final position $n-1$) or completely absent from the array, all $n$ elements must be checked.

### 2.9 Asymptotic Notations
Asymptotic notations are mathematical tools used to describe the growth rate of an algorithm's running time or space requirement as the input size $n$ approaches infinity.

#### 1. Big 'O' Notation ($O$)
* **Definition**: Big $O$ notation specifies the asymptotic **upper bound** of an algorithm's running time. It defines the maximum time an algorithm can take for input size $n$, representing its **worst-case complexity**.
* **Mathematical Statement**: For a function $T(n)$, $T(n) = O(g(n))$ if there exist positive constants $c$ and $n_0$ such that $T(n) \le c \cdot g(n)$ for all $n \ge n_0$.
* **Example**:
  Given running time $T(n) = 3n + 5$. For large $n$, $3n$ dominates the constant $5$, so $T(n) = O(n)$.
* **Common Big $O$ Order Growth Rates**:
  * Constant function $5 \implies O(1)$
  * Linear function $3n + 2 \implies O(n)$
  * Quadratic function $4n^2 + 3n \implies O(n^2)$
  * Cubic function $n^3 + 2n \implies O(n^3)$

#### 2. Omega Notation ($\Omega$)
* **Definition**: Omega notation specifies the asymptotic **lower bound** of an algorithm's running time. It defines the minimum time an algorithm requires, representing its **best-case complexity**.
* **Mathematical Statement**: $T(n) = \Omega(g(n))$ if there exist positive constants $c$ and $n_0$ such that $T(n) \ge c \cdot g(n)$ for all $n \ge n_0$.
* **Example**: In Linear Search over array $[10, 20, 30, 40]$, searching for key $10$ requires exactly $1$ comparison, yielding a lower bound of $\Omega(1)$.

#### 3. Theta Notation ($\Theta$)
* **Definition**: Theta notation provides a **tight bound** (both upper and lower bound simultaneously). It represents the exact asymptotic growth rate of an algorithm, corresponding to its **average-case complexity**.
* **Mathematical Statement**: $T(n) = \Theta(g(n))$ if and only if $T(n) = O(g(n))$ and $T(n) = \Omega(g(n))$.
* **Example**: For $T(n) = 5n^2 + 4n + 2$, the upper bound is $O(n^2)$ and the lower bound is $\Omega(n^2)$, establishing an exact bound of $\Theta(n^2)$.

#### Asymptotic Notations Comparison Summary

| Notation | Mathematical Meaning | Algorithm Case Represented |
| :--- | :--- | :--- |
| **Big $O$ ($O(g(n))$)** | Upper bound (Maximum growth ceiling) | Worst Case |
| **Omega ($\Omega(g(n))$)** | Lower bound (Minimum execution floor) | Best Case |
| **Theta ($\Theta(g(n))$)** | Tight / Exact bound (Exact growth rate) | Average Case |

### 2.10 Time-Space Trade-Off
In computational system design, time and space are competing resources:

* **Principle**:
  * **More Space $\implies$ Less Execution Time**: By utilizing additional memory (such as caching precomputed results or building lookup tables), execution time can be drastically reduced.
  * **Less Space $\implies$ More Execution Time**: When memory is strictly constrained, intermediate values must be repeatedly recalculated, increasing execution duration.

#### Comparative Case Study: Searching an Element
Consider searching for an element in an array of size $n$:

1. **Approach 1: Linear Search**
   * *Mechanics*: Iterates sequentially through array indices.
   * *Time Complexity*: $O(n)$
   * *Space Complexity*: $O(1)$
   * *Trade-off*: Conserves memory space but requires higher execution time.
2. **Approach 2: Hash Table Search**
   * *Mechanics*: Stores elements in key-indexed hash buckets.
   * *Time Complexity*: $O(1)$
   * *Space Complexity*: $O(n)$
   * *Trade-off*: Consumes extra memory for hash storage to achieve instantaneous $O(1)$ search speeds.

### 2.11 Searching Algorithms
Searching is the operational process of finding the position or memory index of a target element in a given list.

#### 1. Linear Search (Sequential Search)
Linear search is the most fundamental searching algorithm. It sequentially examines each element starting from index $0$ until either the key element is matched or the end of the list is reached.

* **Worked Example**:
  Search for `key = 30` in `array = [10, 20, 30, 40, 50]`
  * **Pass 1**: Compare `array[0]` ($10$) with `key` ($30$). $10 \neq 30 \implies$ Advance to next element.
  * **Pass 2**: Compare `array[1]` ($20$) with `key` ($30$). $20 \neq 30 \implies$ Advance to next element.
  * **Pass 3**: Compare `array[2]` ($30$) with `key` ($30$). $30 == 30 \implies$ Match found! Return success at position $3$ (index $2$).

##### Step-by-Step Linear Search Algorithm
* **Step 1**: Start
* **Step 2**: Read the array elements and total size $n$.
* **Step 3**: Read the target search element (`key`).
* **Step 4**: Set loop index variable $i = 0$.
* **Step 5**: Compare $a[i]$ with `key`.
* **Step 6**: If $a[i] == \text{key}$, display "Element found at position $i+1$" and go to Step 9.
* **Step 7**: Otherwise, increment $i$ ($i = i + 1$). Repeat Step 5 while $i < n$.
* **Step 8**: If $i == n$ (all elements checked without match), display "Element not found".
* **Step 9**: Stop.

##### Complexity and Trade-offs of Linear Search
* **Best Case Complexity**: $O(1)$ (Target element is at the first index).
* **Worst Case Complexity**: $O(n)$ (Target element is at the last index or absent).
* **Average Case Complexity**: $O(n)$ (Average number of comparisons is $\frac{n+1}{2}$).
* **Advantages**: Simple to understand and implement; works on both sorted and unsorted lists; requires no auxiliary memory ($O(1)$ extra space).
* **Disadvantages**: Inefficient for large datasets as search time increases linearly with input size $n$.

---

#### 2. Binary Search
Binary search is an efficient searching algorithm based on the **Divide and Conquer** paradigm.
* **Pre-condition**: Array elements **must be sorted** in ascending order before executing binary search.

* **Working Logic**: Binary search locates the middle element $\text{mid} = \lfloor\frac{\text{first} + \text{last}}{2}\rfloor$ and compares it with the target `key`:
  1. If $\text{key} == a[\text{mid}]$, the search terminates successfully.
  2. If $\text{key} < a[\text{mid}]$, the search continues in the left half ($\text{last} = \text{mid} - 1$).
  3. If $\text{key} > a[\text{mid}]$, the search continues in the right half ($\text{first} = \text{mid} + 1$).

* **Worked Numerical Example**:
  Unsorted input: $[10, 6, 16, 18, 80, 75]$. Target `key = 18`.
  * **Pre-processing**: Sort array in ascending order $\implies \text{array} = [6, 10, 16, 18, 75, 80]$ (indices $0$ to $5$).
  * **Iteration 1**:
    * $\text{first} = 0, \text{last} = 5$
    * $\text{mid} = \lfloor\frac{0 + 5}{2}\rfloor = 2 \implies a[2] = 16$
    * Compare: $18 \neq 16$. Since $18 > 16$, search right half: set $\text{first} = \text{mid} + 1 = 3$.
  * **Iteration 2**:
    * $\text{first} = 3, \text{last} = 5$
    * $\text{mid} = \lfloor\frac{3 + 5}{2}\rfloor = 4 \implies a[4] = 75$
    * Compare: $18 \neq 75$. Since $18 < 75$, search left half: set $\text{last} = \text{mid} - 1 = 3$.
  * **Iteration 3**:
    * $\text{first} = 3, \text{last} = 3$
    * $\text{mid} = \lfloor\frac{3 + 3}{2}\rfloor = 3 \implies a[3] = 18$
    * Compare: $18 == 18 \implies$ Key matched! Display success at index $3$ (position $4$).

##### Step-by-Step Binary Search Algorithm
* **Step 1**: Start
* **Step 2**: Initialize $\text{first} = 0$, $\text{last} = n - 1$, and compute $\text{mid} = \lfloor\frac{\text{first} + \text{last}}{2}\rfloor$.
* **Step 3**: Repeat Steps 4 and 5 while $\text{first} \le \text{last}$ and $a[\text{mid}] \neq \text{key}$.
* **Step 4**:
  * If $\text{key} > a[\text{mid}]$, set $\text{first} = \text{mid} + 1$.
  * Else, set $\text{last} = \text{mid} - 1$.
* **Step 5**: Recompute $\text{mid} = \lfloor\frac{\text{first} + \text{last}}{2}\rfloor$.
* **Step 6**: If $a[\text{mid}] == \text{key}$, display "Element found at position $\text{mid}+1$". Else (when $\text{first} > \text{last}$), display "Element not found".
* **Step 7**: Stop.

##### Complexity and Comparison of Binary Search
* **Best Case Complexity**: $O(1)$ (Target element is at the exact initial middle index).
* **Worst Case Complexity**: $O(\log_2 n)$ (Search space is repeatedly halved. For example, $n = 16 \to 8 \to 4 \to 2 \to 1$, requiring at most $4$ steps).
* **Average Case Complexity**: $O(\log_2 n)$.
* **Advantages**: Highly efficient for large datasets; reduces search space logarithmically.
* **Disadvantages**: Strictly requires input data to be sorted; implementation is slightly more complex than linear search.

### 2.12 Array Operations Mechanics
An array is a linear data structure storing elements in contiguous memory locations.

#### 1. Array Traversal Logic
Accesses and prints each array index sequentially from $i = 0$ to $i = n - 1$ using a single loop construct.

#### 2. Array Insertion Mechanics
To insert a new element at a target $1$-based position `pos` ($1 \le \text{pos} \le n + 1$):
1. Shift existing array elements one position to the right starting from index $n - 1$ down to index $\text{pos} - 1$:
   $$a[i] = a[i - 1] \quad \text{for } i = n \text{ down to } \text{pos}$$
2. Store the new element at target index $a[\text{pos} - 1] = \text{element}$.
3. Increment total array element count $n = n + 1$.

#### 3. Array Deletion Mechanics
To delete an existing element from a target $1$-based position `pos` ($1 \le \text{pos} \le n$):
1. Shift surrounding array elements one position to the left starting from index $\text{pos}$ up to $n - 1$:
   $$a[i] = a[i + 1] \quad \text{for } i = \text{pos} - 1 \text{ up to } n - 2$$
2. Decrement total array element count $n = n - 1$.

## 3. Important Definitions

* **Data**: Collection of unorganized raw facts, observations, figures, or symbols lacking standalone meaning.
* **Information**: Processed, structured, and organized data endowed with context and decision-making value.
* **Data Structure**: A specialized format for organizing, storing, and manipulating data in computer memory to enable efficient access and modification.
* **Primitive Data Structure**: Basic data types directly provided by programming languages (e.g., `int`, `float`, `char`).
* **Non-Primitive Data Structure**: Complex data collections constructed using primitive types (Array, Linked List, Stack).
* **Linear Data Structure**: A data structure whose elements are sequentially ordered in a single dimension (e.g., Array, Stack, Queue).
* **Non-Linear Data Structure**: A data structure whose elements are arranged hierarchically or in multi-dimensional networks (e.g., Tree, Graph).
* **Algorithm**: A finite sequence of clear, step-by-step instructions designed to perform a specific task or solve a problem.
* **Time Complexity**: A metric quantifying the total execution time or operation count of an algorithm as a function of input size $n$.
* **Space Complexity**: A metric quantifying the total memory space consumed by an algorithm during execution, comprising fixed and variable parts.
* **Asymptotic Notation**: Mathematical notation ($O, \Omega, \Theta$) used to classify algorithms according to their limiting growth rate as input size approaches infinity.
* **Time-Space Trade-off**: The computational relationship where execution speed can be increased by utilizing extra memory, or memory usage reduced by increasing execution time.
* **Linear Search**: A sequential search method that compares each list element against a key until a match is found or the list ends.
* **Binary Search**: A divide-and-conquer search method that repeatedly halves a sorted search interval to locate a key.
* **Array Traversal**: The operation of sequentially visiting and processing every element stored in an array.

## 4. Algorithms and Their Explanations

### 4.1 Linear Search Algorithm
```
Algorithm: LINEAR_SEARCH(A, N, KEY)
Input: Array A of size N, Target value KEY
Output: Position of KEY if found, or failure message

Step 1: Start
Step 2: Initialize index variable i = 0
Step 3: Repeat Step 4 while i < N
Step 4:     If A[i] == KEY then
                Display "Element found at index: ", i
                Go to Step 7
            Else
                Set i = i + 1
Step 5: End While
Step 6: Display "Element not found in array"
Step 7: Stop
```
* **Explanation**: The algorithm sets index variable $i = 0$ and iterates sequentially through the array. At each index, it tests whether $A[i] == \text{KEY}$. If true, it outputs the matching index and halts immediately. If the loop completes without a match ($i == N$), it outputs a failure notification.

---

### 4.2 Binary Search Algorithm
```
Algorithm: BINARY_SEARCH(A, N, KEY)
Input: Sorted Array A of size N in ascending order, Target value KEY
Output: Index position of KEY if found, or failure message

Step 1: Start
Step 2: Set LOW = 0, HIGH = N - 1
Step 3: Repeat Steps 4 through 6 while LOW <= HIGH
Step 4:     Set MID = (LOW + HIGH) / 2
Step 5:     If A[MID] == KEY then
                Display "Element found at index: ", MID
                Go to Step 8
            Else If KEY > A[MID] then
                Set LOW = MID + 1
            Else
                Set HIGH = MID - 1
Step 6: End While
Step 7: Display "Element not found in sorted array"
Step 8: Stop
```
* **Explanation**: Initializes search boundary pointers $\text{LOW} = 0$ and $\text{HIGH} = N - 1$. Calculates midpoint index $\text{MID}$. If the target $\text{KEY}$ matches $A[\text{MID}]$, search terminates. If $\text{KEY} > A[\text{MID}]$, the lower half is eliminated by adjusting $\text{LOW} = \text{MID} + 1$. If $\text{KEY} < A[\text{MID}]$, the upper half is eliminated by adjusting $\text{HIGH} = \text{MID} - 1$. The search space is halved in every iteration until a match occurs or $\text{LOW} > \text{HIGH}$.

---

### 4.3 Array Element Insertion Algorithm
```
Algorithm: ARRAY_INSERT(A, N, POS, ELEMENT)
Input: Array A of size N, 1-based target position POS, value ELEMENT
Output: Updated Array A of size N + 1

Step 1: Start
Step 2: If POS < 1 or POS > N + 1 then
            Display "Invalid Position" and exit
Step 3: Set i = N
Step 4: Repeat Step 5 while i >= POS
Step 5:     Set A[i] = A[i - 1]
            Set i = i - 1
Step 6: Set A[POS - 1] = ELEMENT
Step 7: Set N = N + 1
Step 8: Display "Element inserted successfully"
Step 9: Stop
```
* **Explanation**: Validates target position range. Shifts array elements rightward from index $N-1$ down to index $\text{POS}-1$ to create an empty slot at index $\text{POS}-1$. Places the new `ELEMENT` into $A[\text{POS}-1]$ and increments total size count $N$.

---

### 4.4 Array Element Deletion Algorithm
```
Algorithm: ARRAY_DELETE(A, N, POS)
Input: Array A of size N, 1-based target position POS to delete
Output: Updated Array A of size N - 1

Step 1: Start
Step 2: If POS < 1 or POS > N then
            Display "Invalid Position" and exit
Step 3: Set i = POS - 1
Step 4: Repeat Step 5 while i < N - 1
Step 5:     Set A[i] = A[i + 1]
            Set i = i + 1
Step 6: Set N = N - 1
Step 7: Display "Element deleted successfully"
Step 8: Stop
```
* **Explanation**: Validates index boundaries. Overwrites the deleted element at $A[\text{POS}-1]$ by shifting all subsequent elements leftward by one position from index $\text{POS}$ to $N-1$. Decrements size count $N$.

## 6. Comparisons and Tables

### 6.1 Primitive vs. Non-Primitive Data Structures

| Feature | Primitive Data Structure | Non-Primitive Data Structure |
| :--- | :--- | :--- |
| **Definition** | Basic data types directly supported by C language | Complex data structures formed using primitive types |
| **Data Holding** | Holds a single atomic value | Holds a collection of homogeneous or heterogeneous values |
| **Examples** | `int`, `float`, `char`, `double` | Array, Linked List, Stack, Queue, Tree, Graph |
| **Memory Allocation** | Fixed static memory allocated at compile time | Dynamic or structured static contiguous memory |
| **Operations** | Direct arithmetic and logical operations | Specialized data structure operations (Traversal, Search) |

---

### 6.2 Linear vs. Non-Linear Data Structures

| Feature | Linear Data Structure | Non-Linear Data Structure |
| :--- | :--- | :--- |
| **Arrangement** | Elements arranged sequentially in single line | Elements arranged hierarchically or in net webs |
| **Levels** | Single-level data structure | Multi-level data structure |
| **Traversal** | Single run traverses all elements sequentially | Multiple traversal paths exist (Preorder, Inorder) |
| **Memory Efficiency** | Less space-efficient due to contiguous constraints | Highly space-efficient for hierarchical/sparse data |
| **Examples** | Array, Stack, Queue, Linked List | Tree, Graph, Hash Table |

---

### 6.3 Linear Search vs. Binary Search

| Feature | Linear Search | Binary Search |
| :--- | :--- | :--- |
| **Data Pre-condition** | Works on both sorted and unsorted arrays | Strictly requires input array to be sorted |
| **Search Paradigm** | Sequential scanning | Divide and Conquer |
| **Time Complexity** | $O(n)$ worst case | $O(\log_2 n)$ worst case |
| **Comparison Count** | Up to $n$ comparisons | Up to $\lfloor\log_2 n\rfloor + 1$ comparisons |
| **Best Suited For** | Small datasets or unsorted collections | Large sorted datasets |

### Question 2: Explain Asymptotic Notations (Big O, Omega, Theta) with mathematical meanings and comparison table.
* **Answer**:
  Asymptotic notations quantify the limiting behavior and growth rate of an algorithm's running time as input size $n \to \infty$:

  1. **Big 'O' Notation ($O$) – Upper Bound**:
     * Describes the maximum running time required by an algorithm (worst-case performance).
     * Mathematical definition: $T(n) \le c \cdot g(n)$ for all $n \ge n_0$.
     * Example: Linear Search worst-case time complexity is $O(n)$.
  2. **Omega Notation ($\Omega$) – Lower Bound**:
     * Describes the minimum running time required by an algorithm (best-case performance).
     * Mathematical definition: $T(n) \ge c \cdot g(n)$ for all $n \ge n_0$.
     * Example: Linear Search best-case time complexity is $\Omega(1)$ (found at index $0$).
  3. **Theta Notation ($\Theta$) – Tight Bound**:
     * Describes the exact growth rate by bounding running time from above and below simultaneously (average-case performance).
     * Mathematical definition: $c_1 g(n) \le T(n) \le c_2 g(n)$.

  | Notation | Bound Type | Algorithm Case | Mathematical Condition |
  | :--- | :--- | :--- | :--- |
  | $O(g(n))$ | Upper Bound | Worst Case | $T(n) \le c \cdot g(n)$ |
  | $\Omega(g(n))$ | Lower Bound | Best Case | $T(n) \ge c \cdot g(n)$ |
  | $\Theta(g(n))$ | Tight Bound | Average Case | $c_1 g(n) \le T(n) \le c_2 g(n)$ |

### Question 3: Trace Binary Search algorithm step-by-step for key = 18 on input array = [10, 6, 16, 18, 80, 75].
* **Answer**:
  * **Step 1: Pre-processing (Sorting)**:
    Sort array in ascending order $\implies a = [6, 10, 16, 18, 75, 80]$ (Indices $0$ to $5$). Total size $n = 6$. Target $\text{key} = 18$.
  * **Step 2: Iteration 1**:
    * $\text{first} = 0, \text{last} = 5$
    * $\text{mid} = \lfloor\frac{0 + 5}{2}\rfloor = 2 \implies a[2] = 16$
    * Compare $a[2]$ ($16$) with $\text{key}$ ($18$). Since $18 > 16$, key lies in the right sublist.
    * Update $\text{first} = \text{mid} + 1 = 3$.
  * **Step 3: Iteration 2**:
    * $\text{first} = 3, \text{last} = 5$
    * $\text{mid} = \lfloor\frac{3 + 5}{2}\rfloor = 4 \implies a[4] = 75$
    * Compare $a[4]$ ($75$) with $\text{key}$ ($18$). Since $18 < 75$, key lies in the left sublist.
    * Update $\text{last} = \text{mid} - 1 = 3$.
  * **Step 4: Iteration 3**:
    * $\text{first} = 3, \text{last} = 3$
    * $\text{mid} = \lfloor\frac{3 + 3}{2}\rfloor = 3 \implies a[3] = 18$
    * Compare $a[3]$ ($18$) with $\text{key}$ ($18$). Since $a[3] == \text{key}$, search succeeds!
  * **Result**: Key $18$ found at array index $3$ (position $4$) in $3$ iterations.

### Question 4: Explain the Space Complexity formula S(P) = C + Sp(I) with a concrete example.
* **Answer**:
  Space complexity represents total memory required during algorithm execution. The total space $S(P)$ consists of two primary components:
  1. **Fixed Part ($C$)**: Independent of input instance size. Comprises space for code instructions, simple constants, and fixed scalar variables.
  2. **Variable Part ($S_p(I)$)**: Depends dynamically on input instance attributes $I$ (such as array dimension $n$ or recursion depth). Includes dynamic memory allocations and recursion stacks.

  * **Mathematical Formula**:
    $$S(P) = C + S_p(I)$$

  * **Worked Example**: Consider C function `SUM(A, B)`:
    ```
    Algorithm SUM(A, B):
      1. Start
      2. C = A + B + 10
      3. Stop
    ```
    * *Fixed Part ($C$)*: Instruction code and constant `10` ($1$ memory unit).
    * *Variable Part ($S_p(I)$)*: Three scalar integer variables `A`, `B`, and `C` ($3$ memory units).
    * *Total Space*: $S(P) = 1 + 3 = 4$ memory units.
